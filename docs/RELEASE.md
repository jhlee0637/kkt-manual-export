# 릴리즈 계획

> **주의:** 계획 초안이다. 확정 전에는 사용자가 각 단계의 순서와 범위를 정한다.

## 목표
- 팀에 배포할 작은 실행 파일. 크기가 최우선이다.
- Windows 10/11 먼저, Mac은 내보내기 형식을 확인한 뒤.
- 사용자는 개발자와 비개발자가 섞여 있다.

## 단계
| 버전 | 범위 | 완료 조건 |
|---|---|---|
| 0.1 (CLI, Windows) | 처리 계층(`ingest`, `attach`, `participant-link`)과 `collect`를 하나로 묶은 실행 파일 | 아래 "차단 항목" 해결, 실제 방 1개로 수집→반영 왕복 성공 |
| 0.2 (GUI) | 엔진과 분리한 GUI(후보: Tauri). 방 선택, 수집 시작, 긴급 탈출 안내 | 비개발자가 문서 없이 수집 1회 성공 |
| 0.3 (Mac) | Mac 내보내기 형식 확인과 수집 계층 | Mac 샘플로 골든 외 추가 시나리오 통과 |
| 1.0 | 암호화(2차 목표), 자동 갱신 | 별도 계획 |

## 0.1 차단 항목 (순서대로)
1. **Windows 수집 계층을 Rust로 이식**: 코드는 `kkt-win` 크레이트로 옮겼고 `kkt collect`로 노출했다. Windows에서 빌드해 실제 카카오톡으로 시험하는 일이 남았다.
2. ~~`Ctrl+D` 긴급 탈출 실측~~: 완료. 대화상자가 열린 채 대기 중 `Ctrl+D`로 중단(종료 코드 130), 대화상자 정리, 창 위치 복원을 확인했다.
3. ~~Windows 빌드 환경~~: 완료. Windows에서 빌드해 `kkt.exe` 약 680KB. 실제 `test` 방에서 `collect` 성공.
4. **서랍 사진 저장 자동화**: 사진은 수동 저장 상태다. 0.1에 넣을지, 사진 없는 텍스트 수집만 먼저 낼지 정한다.
5. **공개 전 점검**(저장소를 공개할 때만): LICENSE, 약관·개인정보 고지, 커밋 작성자 메일 노출, 저장소 이름(`kkt-manual-export`).

## 배포물 구성
- 포함: 실행 파일, `README.md`, `docs/SCHEMA.md`, LICENSE
- 제외: `tests/`, `references/`, `AGENT.md`, `data/`, `src/python`(0.1에서 Python 수집을 쓰지 않는 경우)
- 릴리즈 스크립트가 제외 목록대로 묶고, 묶은 결과에 대화 원문·사진이 없는지 검사한다.

## 릴리즈 전 검증
- `python3 -m pytest`, `cargo test --release`, 골든 26/26(Python과 Rust 모두), `build.py --check`
- 바이너리 크기 기록 (현재 약 820KB, 수집 계층 이식 후 재측정)
- 실제 방으로 수집 후 같은 TXT 재반영이 전부 건너뛰어지는지(멱등) 확인
- Windows 10과 11 각각에서 실행 확인

## 위험
- 카카오톡 업데이트로 메뉴 위치·단축키가 바뀌면 수집이 깨진다. 수집은 포커스 확인 후에만 키를 보내고, 실패하면 중단한다.
- 마우스와 키보드를 점유한다. 시작 전에 알리고 `Ctrl+D`로 중단할 수 있어야 한다.
- 계정 약관과 개인정보: 수집한 대화는 사용자 PC에만 두고 저장소에 올리지 않는다.
